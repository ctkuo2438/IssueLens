# M4 公開試用

## GitHub 登入與分析存取權限

公開使用前，後端需要知道誰建立了每筆分析。GitHub OAuth 是由 GitHub 確認帳號身分的登入流程。IssueLens 使用 GitHub 回傳的數字帳號 ID，讓使用者改名後仍能查回原有分析。

登入後，瀏覽器以 `HttpOnly` cookie 攜帶 IssueLens 工作階段的隨機識別值。後端把識別值的雜湊與帳號存在 PostgreSQL，工作階段最長八小時，登出時立即撤銷。GitHub 的授權權杖用於取得帳號身分，分析工具沿用伺服器端的 `GITHUB_TOKEN` 設定。[GitHub OAuth 流程](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps) · [GitHub 帳號 API](https://docs.github.com/en/rest/users/users#get-the-authenticated-user)

建立任務時，後端從工作階段取得帳號 ID，和任務一起寫入 PostgreSQL。查詢結果、訂閱進度、讀取 Trace 及取消時，都會比對該 ID。自己的分析可照常開啟。另一帳號的分析和不存在的分析都回傳 404。已啟用登入的環境中，未登入會收到 401。

三個 OAuth 設定留白時使用原本的本機模式，可查詢尚未綁定帳號的歷史分析。綁定帳號的分析由對應帳號在登入模式查詢。

## 本機設定

在 GitHub 的 **Settings → Developer settings → OAuth apps** 建立一個 OAuth App，首頁填入 `http://127.0.0.1:3000`，回呼網址填入 `http://127.0.0.1:3000/api/v1/auth/github/callback`。取得 Client ID 和 Client Secret 後，在本機 `.env` 加入以下設定，並保留 M3 設定的 PostgreSQL 連線。[GitHub 註冊說明](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/creating-an-oauth-app) · [M3 資料庫設定](m3.md#本機設定與啟動)

```dotenv
GITHUB_OAUTH_CLIENT_ID=your-client-id
GITHUB_OAUTH_CLIENT_SECRET=your-client-secret
GITHUB_OAUTH_CALLBACK_URL=http://127.0.0.1:3000/api/v1/auth/github/callback
```

使用和回呼網址相同的瀏覽器來源。例如回呼填 `127.0.0.1` 時，從 `http://127.0.0.1:3000` 開啟網站。遠端回呼使用 HTTPS。

```bash
uv run --locked python scripts/dev.py
```

畫面應顯示 **Sign in with GitHub**。登入後會顯示 GitHub 帳號名稱，並可建立分析。

## 兩個帳號驗收

用兩個獨立的瀏覽器設定檔分別登入帳號 A 和 B。各建立一筆分析並保留網址，重新開啟自己的網址應可看到結果。交換網址後，兩邊都應顯示找不到分析。再用原帳號開啟原網址確認結果仍在。建立分析會呼叫 GitHub 和模型 API。

以下整合測試使用真實 PostgreSQL、FastAPI 和 Worker，GitHub 登入回應與分析內容使用測試資料。

```bash
ISSUELENS_TEST_DATABASE_URL=postgresql://issuelens@127.0.0.1:5432/issuelens_test \
  uv run --locked python -W error::RuntimeWarning -m unittest discover -s tests -p 'test_auth.py' -v
```

兩個測試身分均可取得自己的結果、進度及 Trace。交叉讀取與取消均回傳 404。測試也涵蓋登出撤銷、新 API 實例讀回工作階段、GitHub 改名後仍可查詢，以及本機歷史分析的存取。[整合測試](../tests/test_auth.py)

兩個隔離的 Chrome 工作階段也經由正式建置的 Next.js、FastAPI 和 PostgreSQL 完成模擬登入與分析。兩邊能看自己的草稿，開啟對方網址會顯示找不到分析，登出後原網址回傳 401。完整回歸 304 項通過，包含 15 項真實 PostgreSQL 檢查。Pyright 與 Next.js 正式建置通過。真實 GitHub 登入可在設定 OAuth App 後按上面的流程驗收。

面試可討論資料庫工作階段的取捨。每次查詢需要確認工作階段是否有效，代價是多一次資料庫讀取，優點是登出後能立刻撤銷登入。公開試用的下一步是限制每個帳號可建立分析的頻率，避免單一帳號耗盡共用模型額度。
