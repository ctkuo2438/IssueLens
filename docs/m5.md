# M5: Use IssueLens in Claude Code and Codex

M5 exposes the IssueLens analysis to Claude Code and Codex as a local stdio MCP server with one tool, `analyze_github_issue`. Both clients ran real analyses through it, including from the installed package. `v0.1.0` was the first public release; a real analysis through its GitHub install completed, driven by a test script rather than a client. `v0.2.0` adds the server reads from M2 ([Server reads](m2.md#server-reads)), so the model makes fewer requests. The user has not reviewed any report yet.

## Use

To install without a clone, follow the [README install steps](../README.md#use-it-in-claude-code-or-codex). From a checkout, set `OPENAI_API_KEY` in `.env` ([M1 setup](m1.md#setup)) and replace `/path/to/IssueLens` with the project's absolute path:

```bash
claude mcp add --scope user issuelens -- uv run --directory /path/to/IssueLens --locked issuelens-mcp
codex mcp add issuelens -- uv run --directory /path/to/IssueLens --locked issuelens-mcp
```

Claude Code's default tool timeout, about 28 hours, is enough. Codex stops a call after 60 seconds, so add `tool_timeout_sec = 180` under `[mcp_servers.issuelens]` in `~/.codex/config.toml` to cover the 90-second job limit plus queue time, and confirm it with `codex mcp get issuelens`. Then ask:

```text
Use IssueLens to analyze https://github.com/pallets/flask/issues/6146 and tell me what information is still missing.
```

An approved call usually takes 20 to 90 seconds and makes up to 8 OpenAI requests, like one web app analysis.

## How it works

The code is in [backend/app/mcp/](../backend/app/mcp/). The tool runs the existing agent in memory mode inside the server process, with the web app's prompts, model, budgets, and seven GitHub tools.

### Protocol

MCP uses JSON-RPC 2.0 ([specification](https://modelcontextprotocol.io/specification/2025-11-25)). Over stdio, the client starts the server and exchanges one JSON message per line. IssueLens supports `2025-11-25` and `2025-06-18`, which match for its methods, and answers other requested versions with `2025-11-25`. It answers the stateless 2026-07-28 `server/discover` with method not found, so Claude Code falls back to `initialize`. Codex negotiates `2025-06-18`.

- **Cancellation.** Each `tools/call` runs in its own asyncio task. `notifications/cancelled` stops the analysis without a response, as the specification requires, and closing stdin cancels running analyses.
- **Progress.** With a `progressToken` in `_meta`, each new Activity event sends a `notifications/progress` with its text and no `total`. The protocol layer counts, so progress always increases. Bursts send only the newest event, text stops at 200 characters, and nothing follows the call's end.
- **Errors.** Unknown tools and malformed messages get JSON-RPC errors. Bad arguments, a missing key, a non-issue URL, configuration errors, and failed analyses return `isError: true`; only failed analyses reach a model request.
- **stdout.** The server keeps a duplicate of stdout for protocol messages and points file descriptor 1 at stderr, so stray output cannot corrupt the protocol.

### Report

The JSON report's first field, `notice`, says it is third-party data, not instructions, as do the tool description and the server's `instructions`. `sources` omits raw excerpts, and issue text imitating a heading or system message stays a string value. There is no `structuredContent`, because a client that sent it and the text to the model would pay twice; adding it is undecided.

<a id="settings-file"></a>
### Settings

Variables in the server's environment win. The rest comes from one `.env`: the checkout's when `pyproject.toml` sits next to `backend/`, otherwise `~/.config/issuelens/.env`. Claude Code passes the whole shell environment, but Codex passes only nine variables, such as `HOME` and `PATH`, so an exported key misses Codex. Both pass `HOME`, so both read the same file, and keys stay out of the plain-text client configuration. The missing-key error names the file, showing home as `~`. The server ignores `DATABASE_URL` and OAuth settings, and an unset `OPENAI_REASONING_EFFORT` means `medium`.

<a id="context-budget"></a>
### Context budget

Each model request's budget defaults to 24,000 tokens (`AGENT_CONTEXT_TOKENS`, 2,000 to 32,000). It caps IssueLens's own estimate, not the model's window, and requests grow only with the evidence.

At the old 12,000, both client live runs of `pallets/flask#6146` ended `partial` without S5, the newest maintainer comment. Fixed costs and the largest reserves left about 2,300 tokens for evidence, and the frozen M2 Context Builder skips excerpts shorter than its 90-token omission notice, so it omitted S5, the highest priority, instead of the short S2 to S4.

One real run at 24,000 ended `completed` with S5 cited and almost the same usage. Its largest request would also fit in 12,000, so this one run does not show that 12,000 always fails. M2 was evaluated at 12,000 ([Context Builder](m2.md#context-builder)), and 24,000 is not re-evaluated on other issues. Analyses interrupted under 12,000 do not resume, because the checkpoint signature includes the budget.

## Limits

- The 24,000 default was verified on one issue only; M2 ran at 12,000. Evidence-heavy issues make larger requests and more often hit the 90-second limit, and a tight budget can still omit the highest-priority comment.
- Calls spend the operator's OpenAI credit with no daily cap, and Claude Code's auto permission mode calls without asking. At most two run at once; up to 30 live only in process memory until the client restarts.
- Only the two 2025 protocol versions work. Progress shows only the newest event, Codex's non-interactive mode hides it, and interactive display is unconfirmed.
- With `GITHUB_TOKEN` set, only public repositories are analyzed. Prompt injection is reduced, not prevented.
- A first start from GitHub downloads about 38 packages, plus Python if none is 3.13 or later, so the README requires `startup_timeout_sec = 30`, untested on slow networks. Each `@v0.1.0` start fetches the tag, so offline starts fail, although the README at the tag says they work.
- Search covers issues only, so a report does not see pull requests, such as rejected attempts at the same change.
- Not verified: the GitHub install driven by Codex (Claude Code ran one analysis with `v0.2.0`), an outside installer following the README, the default-mode approval prompt, cancelling from Claude Code, exceeding the Codex timeout, IDE or desktop launches, and Windows.
- The generic package name `backend` relies on `uvx` isolation. Installs include the web app and PostgreSQL dependencies, and `psycopg` loads at startup.

## Tradeoffs and exercises

- **Own protocol or SDK.** Ours keeps negotiation and cancellation visible with few dependencies, but we track specification changes ourselves.
- **One full analysis or fine-grained tools.** The bounded, cited analysis adds what `gh` lacks but is slow and paid; fine-grained tools leave quality to the user's model.
- **Version pin.** No version ships every `main` commit; a tag is fixed but upgrades by hand; a full SHA starts offline but is hard to read.

**Exercise.** From the project root, run:

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":0,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{}}}' \
  '{"jsonrpc":"2.0","method":"notifications/initialized"}' \
  '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"analyze_github_issue","arguments":{"issue_url":"https://github.com/pallets/flask/pull/1"}}}' \
  | uv run --locked issuelens-mcp
```

Expect `2025-11-25` instead of `2024-11-05`, the tool list, and `isError: true` for the PR URL, before any model request. Think about why the server answers with its own version instead of rejecting the request. Do not swap in a real issue URL: that makes paid model requests.
